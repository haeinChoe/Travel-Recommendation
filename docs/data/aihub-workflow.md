# AI Hub 데이터 작업 절차

이 문서는 AI Hub 원본 데이터를 탐색·전처리·분석할 때 데이터 손상, 재현성 저하, 원치 않는 데이터 공개를 줄이기 위한 작업 절차를 정의한다. 실제 데이터별 이용 조건이나 컬럼 의미는 해당 데이터의 공식 근거로 확인한다.

## 분석 대상 데이터셋

사용자가 지정한 여행로그 분석 대상은 2023년 국내 여행로그 데이터의 다음 네 권역이다.

- 국내 여행로그 데이터(수도권) (2023)
- 국내 여행로그 데이터(서부권) (2023)
- 국내 여행로그 데이터(동부권) (2023)
- 국내 여행로그 데이터(제주도 및 도서지역) (2023)

권역 간 비교가 작업 목적이면 네 데이터셋을 공통 기준으로 처리한다. 개별 Issue가 특정 권역만 지정하면 그 범위만 작업한다. 같은 권역의 다른 연도 데이터나 비슷한 이름의 데이터셋으로 임의 대체하지 않는다. 사용자가 제공한 AI Hub 내 신청 데이터 목록은 대상 이름을 식별하는 근거로 쓰되, 실제 다운로드 전에는 해당 권역 데이터셋 각각의 승인 상태와 이용 조건을 확인한다.

AI Hub 웹페이지의 `dataSetSn`과 aihubShell의 `datasetkey`는 서로 다른 식별자일 수 있다. 이름 목록에서 각 권역의 Shell `datasetkey`를 확인한 뒤, `-mode l -datasetkey <datasetkey>`로 파일명·용량·`filekey`를 조회한다. Shell 목록 조회는 파일 다운로드와 별개의 메타데이터 조회다. 네 `datasetkey`와 파일 목록을 Issue에 기록해 선택 근거를 검토한다.

## AI Hub API 도구 선택

AI Hub 공식 오픈 API 안내는 같은 API Key로 aihubShell과 AI Hub MCP를 사용할 수 있다고 설명한다. 두 도구의 역할은 다르다.

| 도구 | 용도 | 데이터 다운로드 |
| --- | --- | --- |
| AI Hub MCP | 데이터셋 검색, 상세 메타데이터와 설명서 조회 | 지원하지 않음 |
| aihubShell | 목록·파일 구조 조회와 승인된 데이터 파일 다운로드 | 지원 |

### MCP로 후보 데이터 탐색

MCP는 AI Hub API Key를 MCP 클라이언트의 로컬 설정에 연결해 사용한다. 공식 서버는 AIHUB_API_KEY 환경변수를 읽고 X-API-KEY 헤더로 전달한다. 키는 저장소 설정, Issue, PR, 프로젝트 공유 설정에 넣지 않는다. 사용하는 MCP 클라이언트의 사용자별 로컬 설정 또는 비밀 관리 기능에 둔다.

데이터셋 이름이나 키워드로 후보를 검색하고, 필요한 경우 결과 개수와 offset을 제한한다. 제공되는 도구에는 searchDataSets, countDataSets, describeDataSet, getDataSet, getDataSetsWithGuide가 있다. 후보 데이터의 상세 설명과 데이터 설명서·구축활용가이드를 확인한 뒤 AI Hub 웹사이트에서 정확한 데이터셋·버전과 다운로드 승인 여부를 확인한다. MCP 응답은 메타데이터 탐색 자료이며, 다운로드 승인을 대신하거나 실제 파일을 내려받지 않는다.

### API Key 로컬 보관

API Key는 저장소 안에 두지 않는다. WSL의 Linux 홈 디렉터리(`/home/...`)에 있는 암호화된 `pass` 저장소 같은 개인 비밀 저장소에 넣고, 필요할 때만 현재 셸의 비내보내기 변수로 읽는다. 저장소 루트나 `/mnt/c` 아래에 평문 키 파일을 두는 방법은 사용하지 않는다. `pass`가 없다면 사용자가 선택한 OS 비밀 저장소를 사용한다. `.gitignore`의 `.env`, `.aihub/`, `.secrets/`, `aihub-api-key*` 규칙은 실수 방지용이며 비밀 저장소를 대신하지 않는다.

~~~bash
pass insert aihub/api-key
AIHUB_API_KEY="$(pass show aihub/api-key)"
~~~

MCP 서버에 키를 전달할 때는 MCP 클라이언트가 지원하는 로컬 비밀 저장소 참조 기능을 우선한다. 그런 기능이 없으면 사용자 전용 로컬 설정 파일만 사용하고, 저장소에 커밋되거나 프로젝트 구성원에게 공유되는 설정에는 넣지 않는다. 해당 로컬 설정 파일의 접근 권한도 사용자만 읽고 쓸 수 있게 제한한다.

aihubshell은 공식 사용법상 `-aihubapikey` 인자로 키를 받으므로 실행 중 프로세스 목록이나 시스템 진단 정보에서 키가 잠시 보일 수 있다. 숨김 입력 또는 `pass`는 셸 기록에 키 문자열이 남는 위험을 줄이지만 이 프로세스 인자 노출은 막지 못한다. 개인 WSL 세션에서만 실행하고, 공유 호스트·CI·명령 추적(`set -x`)이 켜진 셸에서는 사용하지 않는다. 작업 직후에는 `unset AIHUB_API_KEY`로 현재 셸 변수도 지운다.

다운로드 호출 예시에서는 위에서 읽은 변수를 사용하고, 키 값을 명령에 직접 입력하지 않는다.

~~~bash
aihubshell -mode d \
  -datasetkey "$AIHUB_DATASET_KEY" \
  -filekey "$AIHUB_FILE_KEYS" \
  -aihubapikey "$AIHUB_API_KEY"
unset AIHUB_API_KEY
~~~

### aihubShell 설치와 메타데이터 조회

AI Hub 공식 API Shell 안내와 가이드에서 제공하는 다운로드 주소를 사용한다. 시스템 전역 경로에 sudo로 설치하지 말고 사용자 실행 경로에 둔다.

~~~bash
mkdir -p "$HOME/.local/bin"
curl --fail --location --output "$HOME/.local/bin/aihubshell" https://api.aihub.or.kr/api/aihubshell.do
chmod 700 "$HOME/.local/bin/aihubshell"
"$HOME/.local/bin/aihubshell" -help
~~~

사용자 실행 경로가 PATH에 없다면 셸 설정에서 추가하거나 위와 같이 전체 경로로 실행한다. 우선 목록 모드로 데이터셋 key와 파일 key, 파일명, 용량을 조회한다. 필요한 파일 key를 특정하고 데이터 상세페이지의 설명·공지와 이용 조건을 함께 확인한다.

~~~bash
aihubshell -mode l
aihubshell -mode l -datasetkey "$AIHUB_DATASET_KEY"
~~~

여행로그 대상 후보는 데이터셋 이름으로 목록에서 찾는다. 목록 조회 결과의 제목이 대상명과 정확히 일치하는지 확인하고, 각 권역의 datasetkey를 따로 기록한다.

~~~bash
aihubshell -mode l | grep -F '국내 여행로그 데이터'
~~~

데이터패키지를 조회하는 경우에는 공식 도움말의 package 모드와 매개변수 이름을 그대로 확인한다. 데이터셋 key와 데이터패키지 key를 혼동하지 않는다.

### 승인된 파일 다운로드

실제 파일을 내려받기 전에 Issue에서 다음을 모두 확인한다.

- 데이터셋과 버전이 특정되어 있음
- AI Hub 웹사이트에서 해당 데이터의 다운로드 승인이 완료됨
- Issue에서 API Shell 다운로드와 로컬 원본 접근 권한이 선택됨
- 필요한 파일 key와 예상 총 용량을 확인함
- 다운로드·병합·압축 해제에 필요한 여유 디스크 용량을 확보함

공식 가이드는 다운로드한 데이터 크기의 약 2~3배 공간을 확보하라고 안내한다. 필요한 일부 파일만 받을 때는 filekey를 명시한다. filekey를 생략하면 전체 파일이 내려올 수 있으므로 전체 데이터가 Issue 범위에 포함된 경우에만 생략한다. 다운로드는 명령을 실행한 현재 디렉터리에 생성된다. 목적 디렉터리로 먼저 이동한 뒤 실행한다.

아래 예시는 키를 명령 문자열에 직접 쓰지 않도록 숨김 입력을 사용한다. API Shell은 다운로드 모드에서 API Key를 명령행 인자 -aihubapikey로 받는다. 숨김 입력은 키가 셸 명령 기록에 문자 그대로 남는 것을 피하지만, 실행 중인 프로세스의 인자에는 값이 전달될 수 있다. 따라서 공유 서버나 CI에서 실행하지 말고, 신뢰할 수 있는 개인 WSL 세션에서만 사용한다. AIHUB_API_KEY 값을 출력·복사·기록하지 않는다.

~~~bash
DATASET_VERSION="dataset-version"
AIHUB_DATASET_KEY="dataset-key"
AIHUB_FILE_KEYS="file-key-1,file-key-2"

mkdir -p "data/raw/$DATASET_VERSION"
cd "data/raw/$DATASET_VERSION"
(
  read -r -s -p "AI Hub API Key: " AIHUB_API_KEY
  printf '\n'
  trap 'unset AIHUB_API_KEY' EXIT

  aihubshell -mode d \
    -datasetkey "$AIHUB_DATASET_KEY" \
    -filekey "$AIHUB_FILE_KEYS" \
    -aihubapikey "$AIHUB_API_KEY"
)
~~~

API Key에 특수문자가 있어도 인자 전체를 큰따옴표로 감싸 변수 확장이 하나의 인자로 유지되도록 한다. 실제 API Key를 명령 예시, 스크립트, Issue, PR, 로그, Notebook에 적지 않는다. 실패한 다운로드를 재시도하기 전에 현재 디렉터리의 일부 파일과 여유 공간을 확인해 중복 다운로드나 공간 부족을 피한다.

AI Hub 안내에 따르면 aihubShell은 다운로드 파일을 병합하고 압축을 풀며, 압축 파일을 제거할 수 있다. 추출된 파일이 이 저장소에서 취급할 raw 원본이다. 이후 전처리에서 수정하지 않는다. 선택한 filekey, 데이터셋 버전, 예상·실제 파일 목록, 크기, 실행 일시와 공개 가능한 checksum을 비밀정보 없이 기록한다.

## 작업 시작 조건

### 승인된 데이터셋 후보 찾기

후보 조사와 사용자의 다운로드 승인 확인을 분리한다.

1. Issue의 분석 목적과 검색어를 기준으로 MCP 검색 또는 `aihubshell -mode l` 목록에서 공개 데이터셋 후보를 찾는다. Shell 목록은 개방 데이터셋 전체 탐색에 사용하고, 필요하면 `grep`으로 키워드를 좁힌다.
2. 후보별 공식 설명·이용 조건·버전·코드북을 확인한다. `aihubshell -mode l -datasetkey <datasetkey>`로 파일명, `filekey`, 용량을 조회하고 Issue에 후보와 선택 근거를 적는다. 이 명령은 메타데이터 조회이며 다운로드가 아니다.
3. 사용자는 AI Hub 계정으로 해당 데이터셋 상세페이지의 다운로드 버튼을 눌러 승인 신청·승인 상태를 확인한다. 공식 안내는 다운로드 전에 이 페이지에서 승인 여부를 확인하도록 요구한다.
4. 에이전트는 AI Hub MCP나 일반 Shell 목록으로 사용자의 개인 승인 데이터셋 목록을 확인할 수 있다고 가정하지 않는다. 공식 API 설명에서 MCP는 메타데이터 조회용이고 Shell 목록은 개방 데이터셋 및 파일 정보 조회용이다. 개인 승인 여부는 사용자가 데이터셋별로 확인해 Issue에 알려준다.
5. 사용자가 승인 상태와 datasetkey, 필요한 filekey를 Issue에 기록하고 다운로드 권한을 선택한 뒤에만 에이전트가 파일 크기와 여유 공간을 확인해 지정 파일을 받는다.

실제 데이터 처리는 사용자가 지정한 Issue에 다음 근거와 권한이 기록된 경우에만 시작한다.

- AI Hub 데이터셋의 정확한 이름, 버전 또는 제공 회차
- 공식 출처와 확인한 데이터별 이용·취급 조건
- 데이터 스키마·코드북 등 컬럼 의미의 근거
- 허용된 데이터 접근 수준과 실행 위치
- 처리 목적, 산출물, 검증 방법
- 처리에 필요한 미결정 사항과 담당자 결정

정보가 없거나 서로 모순되면 실제 데이터의 내용을 추정하거나 임의로 보정하지 않는다. 부족한 정보를 Issue에 기록하고 사용자에게 확인한다.

## 접근 권한과 저장 위치

- Issue에 지정된 데이터셋·파일만 접근한다. 다운로드 권한이 선택된 경우 AI Hub 웹사이트의 승인이 완료된 뒤 API Shell로 저장소의 `data/raw/<데이터셋-버전>/`에 받는다. 이미 로컬에 있는 원본은 Issue에 지정된 위치와 권한을 확인한 뒤 읽는다.
- 원본 파일은 불변으로 취급한다. 수정·이름 변경·삭제·덮어쓰기를 하지 않는다.
- 원본은 저장소 루트의 data/raw/<데이터셋-버전>/ 아래에 둔다. 중간 산출물은 data/interim/<데이터셋-버전>/, 최종 전처리 결과는 data/processed/<데이터셋-버전>/에 둔다. 저장소의 .gitignore는 data/ 전체를 제외하므로 이 경로의 내용은 Git에 추가하지 않는다. 결과·실험 산출물은 results/ 또는 mlruns/ 아래에 둔다. 파일을 놓기 전에 ignore 규칙이 적용되는지 확인한다.
- 전처리 결과와 실험 산출물도 위의 Git 제외 위치에 둔다. 실제 데이터에서 파생된 결과는 기본적으로 공유·커밋하지 않는다. 공유가 꼭 필요하면 이용 조건, 개인 식별 가능성, 재식별 위험을 검토하고 Issue에서 별도 승인을 받는다. 안전한 합성 fixture만 tests/fixtures/ 아래에서 버전 관리한다.
- AI Hub API Shell은 승인된 데이터 다운로드 요청에만 사용한다. 다운로드 후 실제 원본을 AI Hub가 아닌 외부 API, 클라우드 스토리지, LLM, 이슈·PR 첨부, 외부 Notebook 서비스로 보내지 않는다. 다른 목적지로 전송해야 한다면 목적지와 데이터 범위를 특정한 사용자의 명시적 지시를 먼저 받는다.
- 자격 증명은 승인된 로컬 환경 변수나 자격 증명 저장소를 사용한다. 코드, 설정 파일, 셸 기록, 노트북, 로그에 값을 남기지 않는다.

## 재현 가능한 처리

논리적인 데이터 흐름은 다음처럼 구분한다.

    원본(raw) → 중간 산출물(interim) → 분석·실험 입력(processed)

위 데이터 경로를 기준으로 사용하며 데이터셋 버전을 디렉터리명에 포함한다. 산출물은 원본을 덮어쓰지 않으며, 가능한 한 동일한 입력과 설정에서 다시 만들 수 있어야 한다.

- 재사용할 전처리 로직은 버전 관리되는 코드와 명시적인 설정으로 구현한다.
- Notebook은 탐색과 시각화에 사용하고, 반복 가능한 최종 변환 로직은 실행 가능한 모듈·스크립트로 분리한다.
- 무작위 추출이나 샘플링에는 seed와 표본 기준을 기록한다.
- 자동 결측 처리, 중복 제거, 이상치 삭제, 카테고리 통합, AI Hub와 TourAPI 매핑 기준을 데이터 특성을 확인하기 전에 임의로 결정하지 않는다.
- 시간 기준 평가 split, 사용자·여행 단위 분리, 중복 이벤트 처리 등 누수에 영향을 주는 결정은 Issue 또는 승인된 결정 문서에 근거를 남긴다.

## 데이터 품질 확인

분석·전처리 전후에 Issue의 목적에 맞춰 다음을 확인하고 비식별 집계로 기록한다.

- 파일 형식, 인코딩, 컬럼명과 데이터 타입
- 행 수, 키의 유일성, 중복 수
- 컬럼별 결측 수와 허용 범위
- 코드북 범주·날짜·수치 범위의 유효성
- 조인·매핑 성공 및 실패 수
- 필터·변환 단계별 입력과 출력 행 수
- 시간 순서 또는 학습·평가 데이터 간 누수 가능성

컬럼 의미와 코드값은 공식 설명이나 승인된 분석 근거로 확인한다. 단순히 값의 모양이 그럴듯하다는 이유로 의미를 부여하지 않는다. 예기치 않은 분포, 코드값, 결측 또는 매핑 결과는 임의로 숨기거나 제거하지 말고 보고한다.

## 추적 정보와 결과 공유

실행마다 실제 데이터 행을 복사하지 않고 다음 재현 정보를 기록한다.

- 데이터셋 이름·버전·파일 목록과 가능한 경우 checksum
- 제공 문서·스키마 버전
- 실행 코드 커밋, 사용 설정, seed 및 처리 시각
- 단계별 행 수와 비식별 품질 지표
- 사용한 split, 필터와 매핑 기준
- 실행 명령과 결과의 로컬 경로

metadata, 로그, Notebook 출력, 그래프와 예시에는 원본 레코드나 개인을 식별할 수 있는 값이 들어가지 않도록 확인한다. Issue·PR에는 필요한 최소한의 집계와 실행 요약만 기록한다. 공유 가능 여부를 확인하지 못한 산출물은 저장소나 GitHub에 첨부하지 않는다.

## CI와 테스트 데이터

실제 AI Hub 원본에 의존하는 검증을 공개 GitHub Actions에서 자동 실행하지 않는다. 전처리 코드의 단위 검증은 직접 만든 합성 fixture 또는 사용 조건을 확인한 작은 비식별 fixture를 사용한다. CI 도입 시에도 실제 데이터 접근이 필요한 분석은 별도의 승인된 실행 환경에서 수행한다.
