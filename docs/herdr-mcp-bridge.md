# Herdr MCP bridge

This repository provides a small stdio MCP server that you register in your user-level Codex config (`~/.codex/config.toml`). It uses Python's standard library, Git for read-only worktree checks, and the installed `herdr` CLI. User-level registration keeps machine-specific paths out of version control.

The bridge exposes three no-argument, read-only tools and two narrowly scoped teardown tools:

- `herdr_server_status` — server status and version fields.
- `herdr_workspace_list` — workspace IDs, labels, and focused state.
- `herdr_agent_list` — agent name, lifecycle status, and pane/workspace/tab IDs.
- `herdr_worktree_remove(workspace_id)` — removes one clean Herdr-linked Git worktree without force.
- `herdr_workspace_close(workspace_id)` — closes one eligible plain workspace or linked-worktree session with verified caller identity, using Herdr 0.9.0+'s guarded single-ID close. Closing a linked session preserves its Git worktree.

The teardown input schema requires exactly one string `workspace_id` and rejects extra properties. The bridge invokes fixed `herdr` argument arrays, sets `HERDR_ENV=1`, and uses an eight-second timeout. It does not accept arbitrary commands, arguments, raw socket requests, force options, arbitrary paths, or pane controls. It does not change sandbox permissions. Treat the local MCP tool surface as a separate capability surface from direct shell commands.

The read-only list tools return an object with an `items` array in both MCP `structuredContent` and JSON text content; the status tool returns its filtered fields as an object. Successful teardown results identify the requested workspace and report whether removal/closure occurred or the target was already absent.

## Teardown safety boundary

Before either mutation, the bridge requires a syntactically valid `HERDR_PANE_ID`, runs `herdr pane current --current`, and accepts the supported `pane_current` response (or legacy `pane_info`) to extract only `result.pane.workspace_id`. It then requires exactly one matching row in the current Herdr workspace inventory. Missing pane context, any CLI error or timeout, an invalid response shape, a missing or invalid workspace field, and zero or multiple inventory matches all fail before agent/worktree inspection or mutation. The bridge does not use `HERDR_WORKSPACE_ID`, focus, or another pane as a fallback. It then reads the Herdr workspace and agent inventories and refuses a focused target or a target with an agent that is `working`, `blocked`, or `unknown` (missing or unrecognized agent status also fails closed). Worktree removal requires exactly one Herdr record linking the requested workspace to a linked checkout. Git must confirm the returned absolute path and branch, the branch cannot be `dev` or `main`, and the checkout must have no tracked changes, untracked files, or ignored files. The bridge omits `--force` from the fixed `herdr worktree remove --workspace <ID>` invocation.

Plain workspace close refuses the caller's workspace, a focused target, a target with an unsettled agent, linked-worktree targets, and a target that owns a linked checkout. The target must have valid plain-checkout provenance, and the primary checkout owner must be unambiguous. A secondary plain workspace may share that checkout; after closing its exact workspace ID, the bridge verifies that the primary owner and checkout record remain. Rows without owner IDs use a unique workspace checkout-path match when available; duplicate path matches fail closed. An unmapped ownerless row blocks closing the primary workspace, but is tolerated for a secondary target. Post-close readback verifies that peer workspaces, the primary owner, Git worktree listings, and checkout statuses remain unchanged.

Linked-worktree session close is separate from worktree removal. The bridge requires exactly one Herdr worktree row associating the target workspace ID, the path in workspace provenance, and one branch; Git must confirm that exact path and branch. It refuses caller/focused targets and targets with unsettled agents before reading or mutating the worktree. It records peer workspace rows and full Git status (including untracked and ignored files) plus `git worktree list`, then invokes exactly `herdr workspace close <ID>`. Afterward, it confirms the workspace is gone and peer workspace IDs, identity, focus, and repository provenance are unchanged. Herdr may omit at most one derived `open_workspace_id` association from a peer's linked-worktree row when it referred to the closed session; the row path, branch, linked flag, and all other peer metadata must remain exact. The linked checkout path, branch, Git worktree list, and full status must remain unchanged. Dirty or ignored files are preserved. This path never invokes `herdr worktree remove`; the removal tool retains its separate clean-checkout requirement.

For every present target, workspace close requires a running Herdr server version of 0.9.0 or newer; older or unrecognized versions fail closed before worktree inspection or mutation. Newer Herdr versions require explicit group intent before closing a primary workspace and its linked workspaces. The bridge never passes group intent. If Herdr returns `workspace_group_close_required`, the bridge reports that refusal without retrying. A missing target is returned as an explicit `already_absent` no-op.

If a CLI call exits nonzero, the MCP error identifies the fixed internal operation step (such as `workspace inventory read`, `caller pane resolution`, or `workspace close`), a safe category (`Herdr refused to close a primary workspace (group close refused)`, `caller pane unavailable`, socket-specific access denial when stderr identifies socket access, generic `permission denied`, `Herdr server unavailable`, or `CLI command failed`), and the numeric exit status. For the fixed `pane current --current` command only, `caller pane unavailable` is used when stderr is a Herdr JSON error with `code: "pane_not_found"` or the previously supported `code: "not_found"`, and exact `message: "pane not found"`. This identifies a pane lookup failure without revealing which pane or any other error text. Other caller-pane errors, including undocumented CLI wording or unexpected error shapes, use the existing general allowlist or remain `CLI command failed`; this classification does not diagnose why the pane could not be resolved. The step name is selected from the bridge's fixed command shapes; command arguments are never included. Classification may inspect stderr internally, but neither stdout nor stderr is returned or persisted. Timeouts and failed readback also return MCP errors. Diagnostics must not contain workspace or pane IDs, local absolute paths, credentials, or data. Do not repeat a failed mutation through a shell, force-remove a checkout, or switch to another workspace. Preserve state; a teardown MCP tool being unavailable or refusing an operation is not authorization to bypass the MCP boundary.

## Setup and use

Install Herdr and Python 3. Add an MCP entry to `~/.codex/config.toml`, replacing both paths with the absolute path to your checkout:

```toml
[mcp_servers.herdr]
command = "python3"
args = ["/absolute/path/to/Travel-Recommendation/scripts/herdr_mcp_server.py"]
cwd = "/absolute/path/to/Travel-Recommendation"
env = { HERDR_ENV = "1" }
env_vars = ["HERDR_PANE_ID"]
```

This is a repository example for the caller-local Codex configuration; changing the tracked file does not update that configuration. Apply the `env_vars = ["HERDR_PANE_ID"]` change in the caller's user-level MCP registration and reload/restart that stdio server so its child receives the pane context. Codex's [configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference) defines `command` as the stdio launcher and `env_vars` as names allowed through to that process. Keep machine-specific script and working-directory paths only in that local configuration.

For each guarded operation, `scripts/herdr_mcp_server.py` invokes `herdr pane current --current` in a child process that inherits the stdio bridge environment. Herdr uses the caller pane identity for `--current`; its CLI reference states that a cross-workspace move keeps the process's launch-time pane handle as an alias that resolves to the moved terminal. The bridge uses only the returned workspace field and requires exactly one current inventory match. A closed or otherwise unresolvable pane, unsupported CLI behavior, or any unexpected response fails closed. It never infers the caller from focus or falls back to the launch-time workspace variable. The MCP process explicitly sets `HERDR_ENV=1` for each Herdr CLI call. ([Herdr pane CLI reference](https://herdr.dev/docs/cli-reference/), [Herdr socket response shape](https://herdr.dev/docs/socket-api/))

Pane resolution, inventory checks, and teardown are separate calls, not one atomic transaction. The bridge resolves the pane again and rechecks its unique inventory match immediately before the destructive call; if the workspace changed or now equals the target, it aborts. A pane can still move after that final check and before the mutation is applied, so the recheck narrows but cannot eliminate the in-flight race. The documented CLI reference does not state a minimum Herdr version for pane-current move-alias behavior; installations that lack the required command/response behavior reject the guarded operation rather than use a fallback.

## Diagnose independent denial paths

These errors arise at different boundaries. Diagnose each through the interface that returned it; one path's failure does not establish failure in another.

| Path | Observable error | Meaning and safe recovery |
| --- | --- | --- |
| Shell Herdr CLI socket access | The direct shell command returns `Operation not permitted` or `EPERM`. | The shell process could not access the Herdr Unix socket in that execution context. This alone does not establish that the registered MCP bridge failed. Check a read-only MCP tool separately and use only the authorized permission profile/execution route for any needed CLI operation; do not broaden permissions to bypass the boundary. |
| MCP caller identity missing, stale, or ambiguous | Teardown reports `Caller pane identity is unavailable`, a redacted Herdr CLI/response error, `Caller workspace identity is missing from the Herdr inventory`, or `Caller workspace identity is ambiguous in the Herdr inventory`. | The bridge cannot resolve one current workspace from its forwarded pane context and current inventory. Missing/closed pane context, CLI failure, unexpected response, zero matches, and duplicate matches all fail closed before agent inspection or mutation. Start a fresh caller process from the active Herdr pane, confirm the MCP stdio registration forwards `HERDR_PANE_ID`, verify the derived workspace appears exactly once in the read-only inventory, then retry only the guarded operation. Never infer identity from focus or substitute `HERDR_WORKSPACE_ID`. |
| MCP tool denied by approval policy | The agent reports `MCP tool call requires approval, but approval policy is never`. | This is an MCP approval-policy denial, not a socket or caller-identity result. Start or resume the agent with the authorized user-level permission profile (`entry-readonly` for inspection or `herdr-implementation` for authorized implementation work). Do not pass `--ask-for-approval never`; first verify MCP access with a read-only tool, then continue to a guarded operation only after caller identity has exactly one current inventory match. |

An MCP CLI failure is reported as a fixed operation step, a redacted error category, and exit status (for example, `Herdr workspace inventory read failed: socket access denied (EPERM) (exit status 1)`). Socket-specific categories are used only when stderr identifies socket access; other permission failures are reported as `permission denied`. Keep an MCP result distinct from a direct shell command's `EPERM`, which says nothing by itself about the bridge path.

For normal recovery, make the caller-local Codex MCP registration forward `HERDR_PANE_ID`, then start/restart the stdio caller process from its active Herdr pane. Herdr's `pane current --current` resolves a moved pane through its launch-time pane alias; it does not depend on the focused pane. Confirm exactly one workspace inventory match before invoking a guarded operation. If pane resolution fails or the match is absent or duplicated, stop and preserve state; do not infer identity from focus or use `HERDR_WORKSPACE_ID`. Once the single match is established, perform the requested operation through its guarded MCP tool and verify its readback. The bridge repeats the pane and inventory check immediately before mutation, but these separate calls cannot prevent a move in the final check-to-mutation window. A shell CLI `EPERM` remains a separate result and must not be used to diagnose the bridge.

## Troubleshooting

- **Herdr CLI not found:** make sure `herdr` is installed and available on the MCP process's `PATH`.
- **Herdr server unavailable:** start or attach to a Herdr session, then retry.
- **Missing, stale, closed, or ambiguous caller context:** check that the caller-local Codex MCP registration forwards `HERDR_PANE_ID`, then start/restart its stdio process from an active Herdr pane. Confirm `herdr_workspace_list` contains exactly one row for the workspace resolved by `pane current --current`. A CLI error, closed pane, malformed result, absent match, or duplicate match must stop the operation. Do not forward a fixed identity or fall back to focus or `HERDR_WORKSPACE_ID`.
- **MCP approval-policy denial:** when the tool reports that approval is required but the policy is `never`, use the authorized user-level permission profile for the agent and omit `--ask-for-approval never` from launch/start commands. Check a read-only MCP tool before an authorized guarded operation.
- **Workspace close refused:** confirm the running Herdr server reports version 0.9.0 or newer. The bridge sends one workspace ID and never requests a group close. If Herdr reports `workspace_group_close_required`, preserve all workspaces and linked worktrees; do not retry with group intent. Plain close refuses a linked-worktree target; use the linked-session close path only when its workspace/path/branch mapping is unique. Use `herdr_worktree_remove` only when intentionally removing a clean linked checkout.
- **`EPERM` / `Operation not permitted`:** if returned by a direct Codex shell Herdr CLI call, it reports that shell process's socket access failure only. It does not establish whether the registered local MCP bridge can access the socket. Check the bridge through its own MCP response and diagnose any MCP-side error separately. Do not bypass the direct shell boundary.
- **Timeout:** check that the local Herdr server is responsive and retry; each CLI call is bounded to eight seconds.

The bridge reads the running server version from `herdr status server --json` before closing any present workspace. It invokes only `herdr workspace close <ID>`; it never supplies a group-close option. Worktree removal uses the fixed `herdr worktree remove --workspace <ID>` command and never supplies `--force`. Socket access must be checked separately through the direct shell and local MCP paths. A direct shell `EPERM` does not establish internal sandbox details or mean MCP registration changed the direct shell's sandbox settings.

## Regression tests

Run `python3 -m unittest tests.test_herdr_mcp_server` from the repository root. The suite includes isolated temporary Git repositories and a fake Herdr 0.9.3 CLI. It verifies exact single-ID close, primary-group refusal, linked-session close with dirty and ignored files preserved, and that the bridge does not connect to or mutate a user's Herdr session.
