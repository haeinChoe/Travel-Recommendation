# 추천 시스템 용어 사전

> **문서 상태 (2026-10-28):** 공통 용어는 [problem-definition-v2.md](problem-definition-v2.md)의 현재 추천 문제와 같은 의미로 읽는다. 이 문서는 용어 정의를 제공하며 v1 코호트나 후보 규칙을 v2 결정으로 승격하지 않는다.


이 문서는 Travel Recommendation 프로젝트에서 반복해서 사용하는 추천 시스템 용어의 **프로젝트 내 의미**를 정리한다. 단순 번역표가 아니라 데이터와 실험 문서를 같은 의미로 읽기 위한 기준이다.

## 사용자 / 여행자

**사용자(user) / 여행자(traveler)**는 추천을 받는 주체다. AI Hub 2023 여행로그에서는 주로 `TRAVELER_ID`로 식별하지만, 식별자의 유효 범위는 해당 데이터 계약을 따른다.

## 여행 / 요청 문맥

**여행 문맥(trip context)**은 특정 여행이나 추천 요청에 관련된 상황 정보다. 여행 목적, 동반자, 목적지, 시기 등이 포함될 수 있다.

장기적인 사용자 특성과 한 번의 여행 문맥은 같은 개념이 아니다.

**요청 문맥(request context)**은 실제 또는 가상의 추천 요청 시점에 알고 있다고 정의한 정보다. 과거 방문 결과를 보고 요청 문맥을 역으로 만들면 안 된다.

## 아이템 / POI

**아이템(item)**은 추천 대상이다. 이 프로젝트의 여행지 추천에서는 주로 **POI(Point of Interest, 방문 장소)**가 아이템이다.

AI Hub의 `POI_ID`와 TourAPI의 `contentid`는 출처가 다른 식별자이며, 별도 근거 없이 같은 ID라고 가정하지 않는다.

## 상호작용

**상호작용(interaction)**은 사용자와 아이템 사이에서 관측된 행동이다. 여행로그의 방문 기록은 대표적인 상호작용이다.

상호작용은 반드시 "좋아함"을 뜻하지 않는다.

## 관측 단위

**관측 단위(observation grain / grain)**는 데이터 행 하나가 무엇을 의미하는지 정의하는 수준이다. 이 프로젝트의 학습 데이터 계약에서는 다음 세 가지 단위를 구분한다.

- **방문 이벤트 단위(`visit_event_grain`: `(region, TRAVEL_ID, VISIT_AREA_ID)`)**: 원시 방문 행 단위이며 여행 내 반복 방문과 방문별 사후 피드백을 보존한다.
- **여행-POI 상호작용 단위(`trip_poi_grain`: `(region, TRAVEL_ID, POI_ID)`)**: 동일 여행 내 같은 장소 반복 방문을 하나의 이진 관측 양성(`observed_positive = 1`)으로 중복 제거한 순위 학습 기본 단위다.
- **여행/요청 문맥 단위(`trip_request_grain`: `(region, TRAVELER_ID, TRAVEL_ID)`)**: 여행 문맥 특성이 결합되고 학습/검증 분할 무결성을 보장하는 단위다.

## 조인 키와 입력 특성

**조인 키(join/grouping key)**는 테이블 간 행을 연결하거나 중복을 제거하고 분할 무결성을 검증하며 후보 아이템을 식별하기 위해 메모리 내에서 사용하는 원시 구분자(`TRAVELER_ID`, `TRAVEL_ID`, `VISIT_AREA_ID`, `POI_ID`, `contentid`)다.

**입력 특성(model feature)**은 추천 모델이 문맥과 장소 사이의 선호 관계를 일반화하기 위해 기계학습 입력으로 사용하는 속성값(여행 스타일, 동기, 동반자, 시기, 권역, 시군구 코드, 관광 분류 등)이다. `POI_ID`와 `contentid` 등 원시 식별자는 조인·집계·후보 식별용 구분자(key)로는 사용할 수 있으나, 기계학습 모델의 입력 특성(feature)으로는 사용하지 않는다.

## 순수 관광 코호트

**순수 관광 코호트(tourism_core_cohort)**는 과거 학습 실험에서 전체 방문 중 자연관광지·역사·문화시설·레저·체험 등의 방문만 추려 만든 집단이다. 당시 식당·카페·쇼핑·숙박·이동 시설의 방문은 양성 집합에 포함되지 않았다. **방문했지만 이 집단에서 제외된 장소**는 방문 기록이 없는 장소와 다르다. 이 분리 규칙을 앞으로도 사용할지는 제품이 추천할 장소 범위가 정해진 뒤 결정한다. 기존 세부 유형 코드와 건수는 [학습 데이터 계약](training-data-contract.md)에 기록돼 있다.

## 학습-서빙 특성 호환성

**학습-서빙 특성 호환성(training-serving feature parity)**은 오프라인 학습 데이터(AI Hub)에서 사용한 입력 특성을 온라인 추론 시점의 추천 후보(TourAPI, 특히 AI Hub 방문 이력과 직접 매칭되지 않은 미매칭 후보)에서도 동일한 의미와 코드 체계로 생성·공급할 수 있는 성질이다. 속성 기반 모델 설계는 미매칭 후보 점수화를 위한 구조적 전제이지만, 개별 특성의 실제 호환성(권역 매핑 확립, 시군구 부분 결측, 카테고리 교차 매핑표 미정의, 인기도 콜드 스타트 기본값 필요)은 특성별로 구분해 검증해야 한다.

## 암묵적 피드백

**암묵적 피드백(implicit feedback)**은 별점처럼 선호를 직접 표현하지 않고 방문, 클릭, 구매 같은 행동으로 관측되는 신호다.

관측된 방문은 실험 계약에 따라 **관측 양성(observed positive)**으로 사용할 수 있다. 반대로 방문하지 않은 장소를 자동으로 음성(negative)으로 해석하지 않는다.

## 관측 양성

**관측 양성(observed positive)**은 데이터에서 실제 상호작용이 관측되어 실험상 양성 신호로 사용하는 항목이다.

이 표현은 "사용자가 실제로 좋아했다" 또는 "추천에 노출되었다"는 뜻이 아니다.

## 미관측 항목

**미관측 항목(unobserved item)**은 데이터에서 상호작용이 기록되지 않은 아이템이다.

현재 추천 실험에서는 별도 노출 또는 음성 표본 계약이 없으면 **알 수 없음(unknown)**으로 다룬다.

## 추천 자격, 후보 집합, 후보 생성

**추천 자격(candidate eligibility)**은 제품 범위와 카탈로그 규칙에 따라 어떤 장소가 추천 대상으로 인정되는지를 뜻한다. 데이터 inventory나 과거 관측이 존재한다는 사실만으로 제품상 추천 자격이 생기지 않는다.

**후보 집합(candidate set)**은 한 추천 요청에서 모델이 고려할 수 있는 장소 목록이다. 평가용 임시 후보 집합은 규칙과 분모를 밝혀 재현하며, 실제 서비스 노출 집합이라고 주장하지 않는다.

**후보 생성(candidate generation)**은 추천 자격이 있는 큰 집합에서 요청별 점수화 대상을 검색·축소하는 선택적 단계다. 후보 자격과 다르다. 직접 점수화가 가능하면 별도 후보 생성이 필요하지 않을 수 있다.

## 노출

**노출(exposure)**은 사용자가 실제로 볼 수 있었거나 선택할 기회가 있었던 아이템을 뜻한다.

여행로그의 방문 기록만으로는 일반적으로 어떤 장소가 사용자에게 노출되었는지 알 수 없다. 따라서 "미방문 = 싫어함"을 정당화하는 근거로 사용할 수 없다.

## 임시 후보 정의

**임시 후보 정의**는 실제 서비스 후보 집합을 직접 관측할 수 없을 때, 분석을 위해 재현 가능한 규칙으로 후보 집합을 임시 정의한 것이다.

실제 서비스의 후보 집합과 같다고 주장하지 않으며, 어떤 규칙으로 대신 정의했는지와 그 한계를 함께 기록한다.

## 식별 / 식별 해소

**식별(identity)**은 서로 다른 데이터 출처의 레코드가 같은 실제 장소를 가리키는지 판단하는 문제다.

**식별 해소(identity resolution)**는 주어진 근거로 두 레코드를 같은 장소로 확정하거나, 모호하거나, 일치하지 않는 것으로 분류하는 과정이다.

식별하지 못했다는 사실은 해당 장소가 외부 카탈로그에 없다는 증거가 아니다.

## 식별자 연결

**식별자 연결**은 서로 다른 데이터 원천의 식별자가 같은 실제 대상을 가리키는지 검증하고, 그 대응 관계를 기록하는 것이다.

이 프로젝트의 대표적인 예는 AI Hub의 `(region, POI_ID)`와 TourAPI의 `contentid` 사이 관계다. 이름이나 주소가 비슷하다는 이유만으로 연결을 확정하지 않는다. 공식 대응 정보, 독립적으로 검증된 좌표 호환성, 신뢰할 수 있는 외부 장소 식별자처럼 별도 근거가 필요하다.

식별자 연결을 확인하지 못했다는 사실은 어느 한쪽 카탈로그에 장소가 없다는 뜻이 아니다. 또한 추천 모델의 학습 관측치 포함 자격은 외부 카탈로그 식별자 연결 여부에 의존하지 않는다.

## 커버리지

**커버리지(coverage)**는 특정 기준이 전체 대상 중 얼마나 포함되는지를 나타내는 비율이다. 반드시 분모를 함께 명시한다.

예:

- 관측 양성 중 후보 집합에 포함된 비율
- 식별 가능한 관측 양성 비율
- 평가 가능한 여행 비율

서로 다른 분모의 커버리지를 같은 지표처럼 비교하지 않는다.

## 콜드 스타트

**콜드 스타트(cold start)**는 학습 또는 기준 데이터에 충분한 이력이 없어 기존 방식으로 점수를 만들기 어려운 사용자나 아이템을 뜻한다.

문서에서는 사용자 콜드 스타트인지, 아이템 콜드 스타트인지, 현재 실험에서 어떤 기준으로 판정했는지 명시한다.

## 기준 모델

**기준 모델(baseline)**은 더 복잡한 방법의 가치를 비교하기 위한 단순하고 재현 가능한 기준이다.

이 프로젝트에서는 예를 들어 권역 인기도 기반 추천이 기준 모델이 될 수 있다. 기준 모델보다 복잡하다는 이유만으로 새로운 모델이 더 낫다고 판단하지 않는다.

## 검색 / 후보 추출

**검색(retrieval)**은 요청에 맞는 일부 장소를 큰 추천 가능 집합에서 찾아 순위화 단계에 넘기는 일이다. 이는 제품상 추천 자격을 정하는 과정과 다르다. Two-Tower/ANN은 가능한 기술 예시일 뿐 이 프로젝트의 고정 계약이 아니다.

## 순위화

**순위화(ranking)**는 후보 아이템의 순서를 정하는 문제다. 추천 시스템의 핵심 평가는 일반 분류 정확도보다 순위 지표가 더 직접적인 경우가 많다.

## Recall@K

**Recall@K**는 실제 관련 항목 중 상위 K개 추천에 포함된 비율이다.

```text
Recall@K = 상위 K개 안에 들어온 관련 항목 수 / 전체 관련 항목 수
```

후보 집합 밖의 관련 항목을 분모에 넣는지 여부는 실험마다 명시해야 한다.

## NDCG@K

**NDCG@K(Normalized Discounted Cumulative Gain)**는 관련 항목이 상위 순위에 배치될수록 더 높은 점수를 주는 순위 지표다.

단순히 "찾았는가"뿐 아니라 "얼마나 위에 놓았는가"를 반영한다.

## MRR

**MRR(Mean Reciprocal Rank)**은 첫 번째 관련 항목이 얼마나 높은 순위에 등장했는지를 평가하는 지표다.

첫 관련 항목의 순위가 1이면 1, 순위가 2이면 1/2처럼 역수를 사용한 뒤 사용자 또는 요청 단위로 평균한다.

## 간접 지표 / 대체 정의

**간접 지표**는 직접 측정하기 어려운 개념을 다른 관측 가능한 값으로 간접적으로 추정할 때 사용하는 지표다. 예를 들어 방문 기록으로 사용자의 선호를 간접적으로 추정할 수는 있지만, 방문과 선호를 같은 개념으로 보지는 않는다.

**대체 정의**는 실제 집합이나 기준을 직접 관측할 수 없을 때 분석을 위해 재현 가능한 규칙으로 임시 정의한 것이다. 무엇을 대신 정의했는지와 원래 개념과의 차이를 함께 기록한다.

## 예측 시점

**예측 시점(prediction time)**은 추천을 생성한다고 가정한 시점이다.

해당 시점 이후에 생긴 만족도, 재방문 의향, 실제 방문 결과 등을 입력 특성으로 사용하면 데이터 누수(leakage)가 발생할 수 있다.

## 데이터 누수

**데이터 누수(data leakage)**는 예측 시점에 알 수 없는 정보나 평가 데이터의 정보를 학습 과정에 사용해 성능이 실제보다 좋아 보이는 문제다.

여행 단위 중복, 사용자 중복, 사후 피드백 사용, VL을 이용한 후보 정의 등을 실험마다 점검한다.

---

새 문서에서 위 용어를 사용할 때는 첫 등장 문맥에서 독자가 이해할 정도의 짧은 설명을 제공하고, 더 자세한 정의가 필요하면 이 문서로 연결한다.
